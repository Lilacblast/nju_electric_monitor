# NJU Dorm Power Dashboard 设计规格

日期：2026-08-28  
状态：已批准实施  
视觉方向：B · 轻量能源摘要

## 1. 目标与边界

在仓库根目录新增一个公开的 GitHub Pages 页面，入口为 `/index.html`，预期部署地址为 `https://lilacblast.github.io/nju_electric_monitor/`。页面仅展示当前单个宿舍的电量记录，不支持登录、搜索、多房间、楼栋或校区视角。

页面完全只读，只请求同仓库的 `data/electricity_data.csv`。它不得调用 NJU 登录或缴费接口，也不得包含用户名、密码、Cookies、Session、Token、GitHub Secrets、姓名、学号或具体宿舍号。现有爬虫与 `.github/workflows/auto_monitor_schedule.yml` 的核心逻辑保持不变。

第一版采用单文件 `index.html`，内联 CSS 与 JavaScript，并通过固定版本的 CDN 加载 Chart.js。页面即使无法加载 Chart.js，也必须继续显示余额、统计和错误状态，不能白屏。

## 2. 视觉系统

采用用户选定的 B 方向：浅暖灰背景、近白内容面、深墨色文字、低饱和电力绿与极细分隔线。默认无装饰性渐变、插画、照片、毛玻璃、霓虹光、图标库或大面积阴影。圆角只用于状态提示、范围切换和必要的容器关系。

字体使用系统字体栈；所有数值启用 `tabular-nums`。页面最大内容宽度约 1180 px。桌面布局适度横向展开，手机以单列和两列统计网格为主。触控按钮高度至少 44 px，320 px 宽度起无页面级横向滚动。

使用 `prefers-color-scheme: dark` 自动切换深色模式，不提供手动开关。深色模式保持相同信息层级，只替换为暖黑背景、近白文字与提亮后的绿色。

## 3. 页面结构

页面自上而下包含：

1. 顶栏：`NJU Power Watch`、只读说明、采集状态与“每小时更新”。
2. 当前余额摘要：最后一条合法记录的余额与北京时间更新时间；旁侧展示预计可用天数和状态。
3. 统计区：最近采样区间、近 24 小时、今日耗电、余额变化或预计可用。手机为两列；数据不足显示 `—`。
4. 余额趋势：24h、7天、30天、全部四档，默认 24h；折线不强制从零开始；充值节点使用绿色标记和 `+N` 标签。
5. 区间耗电：柱状图展示每个实际采样区间的耗电量；tooltip 同时显示区间时长与平均负载 W。
6. 充值记录：最多十条，高置信度显示推测充值量、净增与同期耗电；低置信度显示“疑似充值 / 转电”。
7. 低余额预警：根据余额分级，并在预测可用时附剩余天数。
8. 趣味换算：基于最近 24 小时耗电给出手机充电、空调运行与电动车里程的粗略类比，明确标注仅为估算。
9. 页脚：数据来源为仓库静态 CSV、自动刷新说明与非官方只读声明。

## 4. 数据读取与标准化

请求地址为 `data/electricity_data.csv?t=${Date.now()}`，并设置 `cache: "no-store"`。页面加载后立即读取，此后每五分钟重新读取，不刷新整页。若刷新失败但已有成功数据，保留旧数据并显示非阻塞错误提示；首次读取失败则显示“数据读取失败”。

CSV 解析支持首行字段名与带引号字段。每行映射为 `{ time, balance, unit }`。`num` 必须是有限数字，`time` 必须能解析；非法行跳过。无时区 ISO 时间按北京时间解释；带时区时间按原时区解析后统一以 `Asia/Shanghai` 显示。

标准化流程：

1. 跳过非法记录。
2. 以时间戳为键，重复时间保留文件中最后一条。
3. 按时间升序排序。
4. 空结果进入“暂无电量记录”；只有一条时只显示余额，统计与图表显示数据不足。

当前数据已重置为当前宿舍的单条记录。生产页面不得把设计预览中的示意历史带入 `index.html`。

## 5. 区间、耗电与充值推断

相邻记录构成一个区间。区间时长为 `(current.time - previous.time) / 3600000`；非正时长区间无效。

- 当 `delta = current.balance - previous.balance <= 0`：`consumption = -delta`，`recharge = 0`。
- 当 `delta > 0`：计算 `estimatedRecharge = ceil(delta / 10) * 10`，`estimatedConsumption = estimatedRecharge - delta`。
- 若 `0 <= estimatedConsumption <= 5`：记为高置信度充值，区间耗电等于 `estimatedConsumption`，并计入 24h、今日与平均耗电。
- 若 `estimatedConsumption > 5`：记为低置信度“疑似充值 / 转电”，区间耗电设为未知，不计入耗电统计或预测。

充值事件统一包含：`time`、`previousBalance`、`currentBalance`、`netIncrease`、`estimatedRecharge`、`estimatedConsumption` 与 `confidence`。

平均功率为 `consumption / hours` kW，tooltip 转成 W 显示。统计窗口按区间结束时间筛选：近 24 小时包含结束时间位于当前时刻前 24 小时内的合法耗电区间；今日包含结束时间位于北京时间当天 00:00 之后的合法耗电区间。

## 6. 预测与状态

预计可用天数使用最近七天内结束的合法区间；若历史不足七天则使用全部合法区间。计算 `dailyAverage = totalConsumption / totalHours * 24`，再计算 `remainingDays = latest.balance / dailyAverage`。

可用于预测的累计区间时长不足 12 小时、日均耗电非正数或余额无效时，显示“数据不足”。低置信度充值区间不参与累计耗电与累计时长。

数据新鲜度以当前时刻与最新记录的差值判断：不超过 2.5 小时为正常；超过 2.5 小时显示黄色“数据可能已停止更新”；超过 6 小时显示红色“采集异常”。

余额分级：`>=20` 正常，`10–20` 提醒，`5–10` 警告，`<5` 严重。只有预测有效时才显示“按近期速度约还能使用 N 天”。

## 7. 图表行为

使用两个 Chart.js 实例并在刷新时更新数据而非重复叠加 canvas。

余额趋势按选定时间范围过滤记录；若过滤后不足两点，显示数据不足占位并隐藏 canvas。折线使用轻微张力或直线，禁止可能产生过冲的强平滑。充值节点通过独立 dataset 或点样式标记。

区间耗电默认展示最近 24 小时内的合法区间。柱图标签使用区间结束时间；tooltip 显示开始与结束时间、耗电量、区间小时数与平均负载。低置信度区间不绘制为零耗电。

## 8. 错误与空状态

- 空文件或无合法记录：显示“暂无电量记录 / 等待第一次采集”。
- 单条记录：显示余额与更新时间，统计、预测、图表显示 `—` 或“至少需要两次采样”。
- CSV 读取/解析失败：显示“数据读取失败”，页面结构仍存在。
- 部分坏行：静默跳过，并在页脚显示跳过数量。
- Chart.js 加载失败：统计继续工作，图表区域显示“图表组件加载失败”。
- 自动刷新失败：保留最后一次成功结果并提示失败时间。

## 9. 可访问性与响应式

所有范围按钮使用原生 `button`，支持键盘焦点、`aria-pressed` 与至少 44 px 触控尺寸。颜色不是状态的唯一编码，状态同时有文字。图表 canvas 提供描述性 `aria-label`，空状态使用可读文本。

桌面统计为四列；中等宽度为两列；手机保持两列，在极窄宽度仍不溢出。图表容器高度随断点调整。长时间和异常文字允许换行。

## 10. 验证策略

计算核心以纯函数组织，并暴露只读测试入口。Node 内置测试通过提取内联核心脚本验证：CSV 解析、非法行、去重排序、普通耗电、两种充值置信度、充值小时耗电计入、非整点区间功率、24h/今日统计、十二小时预测门槛和空/单条记录。

浏览器验证覆盖：真实 CSV 单条记录、合成多记录数据、CSV 失败、Chart.js 失败、范围切换、五分钟刷新定时器、375×812、320×568、1440×900、自动深色模式、无横向溢出与无控制台错误。

部署前扫描 `index.html`，确认不包含 `NJU_USERNAME`、`NJU_PASSWORD`、Cookie、Session、Token、姓名、学号或 Secrets。
